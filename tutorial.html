Introduction to Jest

Jest is a JavaScript testing framework designed to ensure correctness of any JavaScript codebase. It allows you to write tests with an approachable, familiar and feature-rich API that gives you results quickly.

Why Jest?

  • Zero configuration required
  • Built-in code coverage
  • Snapshot testing
  • Interactive mode
  • Excellent documentation
  • Large community support

Installation and Setup

Prerequisites

  • Node.js (version 14 or higher)
  • npm (comes with Node.js)
  • A code editor (VS Code recommended)

Installation Steps

# Create a new project directory
mkdir jest-tutorial
cd jest-tutorial

# Initialize a new npm project
npm init -y

# Install Jest and related dependencies
npm install --save-dev jest @types/jest vite vitest

# Add test script to package.json
{
  "scripts": {
    "test": "vitest",
    "test:watch": "vitest watch",
    "test:coverage": "vitest run --coverage"
  }
}

Configuration

Create a vite.config.js file in your project root:

import { defineConfig } from 'vite'

export default defineConfig({
  test: {
    globals: true,
    environment: 'node',
    include: ['**/*.{test,spec}.{js,jsx,ts,tsx}'],
    coverage: {
      reporter: ['text', 'json', 'html'],
    },
  },
})

Key Concepts

1. Test Structure

describe('Test Suite', () => {
    test('individual test case', () => {
        expect(actual).toBe(expected);
    });
});

2. Common Matchers

Matcher Description Example
toBe() Exact equality expect(2 + 2).toBe(4)
toEqual() Deep equality expect({a: 1}).toEqual({a: 1})
toBeTruthy() Truthy values expect(true).toBeTruthy()
toBeFalsy() Falsy values expect(false).toBeFalsy()
toContain() Array/string contains expect([1,2,3]).toContain(2)
toThrow() Exception testing expect(() => throwError()).toThrow()

3. Async Testing

// Promise-based
test('async test with promises', () => {
    return asyncFunction().then(data => {
        expect(data).toBe('expected');
    });
});

// Async/await
test('async test with async/await', async () => {
    const result = await asyncFunction();
    expect(result).toBe('expected');
});

// Error handling
test('async error handling', async () => {
    await expect(asyncFunction()).rejects.toThrow('error message');
});

4. Mocking

// Mock a function
const mockFn = vi.fn();
mockFn.mockReturnValue('mocked value');

// Mock a module
vi.mock('./module', () => ({
    function: () => 'mocked'
}));

// Mock implementation
mockFn.mockImplementation(() => {
    // custom implementation
    return 'custom value';
});

// Mock async function
mockFn.mockResolvedValue('async value');
mockFn.mockRejectedValue(new Error('async error'));

5. Snapshot Testing

test('snapshot test', () => {
    const component = renderComponent();
    expect(component).toMatchSnapshot();
});

// Update snapshots
// Run: npm test -- -u

Example Structure

Each example in this repository demonstrates different aspects of Jest testing:

  • Basic Testing: Simple function testing and assertions
  • Async Testing: Testing asynchronous code and promises
  • Mocking: Function and module mocking techniques
  • Snapshot Testing: UI component testing
  • Integration Testing: Testing multiple components together

Running Tests

# Run all tests
npm test

# Run tests in watch mode
npm run test:watch

# Generate coverage report
npm run test:coverage

# Run specific test file
npm test -- path/to/test.js

# Run tests matching a pattern
npm test -- -t "pattern"

Test Coverage

Jest provides built-in code coverage reporting. The coverage report shows:

  • Statement coverage
  • Branch coverage
  • Function coverage
  • Line coverage

Best Practices

Writing Good Tests

  • Write tests before implementing features (TDD)
  • Keep tests simple and focused
  • Use descriptive test names
  • Test behavior, not implementation
  • Maintain test independence
  • Follow the AAA pattern (Arrange, Act, Assert)
  • Use meaningful assertions
  • Keep test files organized

Advanced Topics

1. Test Hooks

beforeAll(() => {
    // Runs once before all tests
});

afterAll(() => {
    // Runs once after all tests
});

beforeEach(() => {
    // Runs before each test
});

afterEach(() => {
    // Runs after each test
});

2. Custom Matchers

expect.extend({
    toBeWithinRange(received, floor, ceiling) {
        const pass = received >= floor && received <= ceiling;
        return {
            message: () =>
                `expected ${received} to be within range ${floor} - ${ceiling}`,
            pass,
        };
    },
});

3. Test Timeouts

test('slow test', async () => {
    // Increase timeout for this test
}, 10000);

Common Pitfalls

  • Not cleaning up after tests
  • Testing implementation details
  • Over-mocking
  • Not handling async operations properly
  • Writing brittle tests

Tips for Success

  • Start with simple tests and gradually increase complexity
  • Use the watch mode during development
  • Regularly check test coverage
  • Keep your test files organized and maintainable
  • Use meaningful test descriptions
  • Follow the testing pyramid (unit > integration > e2e)
